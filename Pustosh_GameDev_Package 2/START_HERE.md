# «Пустошь» — пакет для разработки игры

Версия пакета: **3.0** · 28.10.2026

Полный пакет для разработки 2D-игры на выживание в открытом постапокалиптическом мире с видом сверху. **Игра пишется как веб-игра на TypeScript + Phaser.** Она без изменений загружается в **Яндекс Игры**, а для **RuStore** заворачивается в Android-приложение через **Capacitor**. Одна кодовая база.

Пакет рассчитан на то, чтобы отдавать его нейросети-разработчику (ИИ-агенту) по шагам.

## Что внутри

| Путь | Что это |
| --- | --- |
| `START_HERE.md` | этот файл |
| `TZ/00_OVERVIEW.md` | общее ТЗ: стек, архитектура, сборки, правила кода, требования к качеству |
| `TZ/GDD.md` | дизайн игры: цикл, мир, биомы, враги, боссы, крафт, строительство, прогрессия, реклама |
| `TZ/ASSETS.md` | каталог ассетов, масштаб и привязка, известные дефекты |
| `TZ/ANIMATIONS.md` | каталог всех анимаций и эффектов с привязкой к шагам и приоритетом |
| `TZ/STEP_01 … STEP_10` | 10 шагов разработки: задачи, критерии приёмки, готовый промпт для ИИ |
| `data/*.json` | игровые данные: 149 предметов, 149 рецептов, 23 станка, 21 вид защиты, 16 врагов и зверей, 6 боссов, 6 биомов, 7 машин, навыки, баланс, скелеты |
| `data/README.md` | что лежит в каждом файле данных |
| `assets_manifest.json` | все 723 спрайта: путь, размер, исходный лист, статус, размер в игре, точка привязки |
| `assets/` | нарезанные спрайты (PNG с прозрачностью) |
| `source_sheets/` | исходные листы из ChatGPT (`archive/` — старые и отклонённые, не использовать) |
| `previews/` | контрольные превью нарезки |
| `tools/` | скрипты нарезки и генерации данных (Python), образец ракурса, шаблон промпта для новых картинок, демо анимации |

## Как работать с ИИ-агентом

1. Дай агенту весь пакет как рабочую папку (новый пустой репозиторий + эта папка рядом или внутри как `docs/package`).
2. **Первое сообщение:**

   > Ты ведущий разработчик веб-игр на TypeScript и Phaser. В папке лежит пакет игры «Пустошь». Прочитай `START_HERE.md`, `TZ/00_OVERVIEW.md`, `TZ/GDD.md`, `TZ/ASSETS.md`, `TZ/ANIMATIONS.md` и `data/README.md`. Ничего не пиши в код, пока не прочитаешь. Ответь коротким планом, как ты понял архитектуру, и вопросами, если они есть.

3. Дальше по одному шагу: открой `TZ/STEP_XX_*.md`, скопируй блок «Промпт для ИИ» и отправь агенту. Следующий шаг — только после всех «Критериев приёмки» текущего.
4. После каждого шага проверь сам: `npm run dev`, сборки для Яндекса и Android, чек-лист шага.
5. Не позволяй агенту молча менять `data/*.json` и картинки — любые изменения отдельным коммитом с объяснением.

## Порядок шагов

| Шаг | Результат | Играбельно? |
| --- | --- | --- |
| 1 | Проект на Phaser, сборки для Яндекса и Android, заглушки платформ, **замер FPS на слабом телефоне** | пустая сцена |
| 2 | Атласы, загрузка и проверка данных, галерея ассетов | галерея |
| 3 | Мир из чанков, биомы, тайлы, объекты, камера, коллизии, день и ночь, ветер и вода | ходит камера |
| 4 | Герой: управление, анимация по частям, выживание, смерть | герой ходит |
| 5 | Инвентарь, добыча, инструменты, лут, подсветка | можно собирать |
| 6 | Крафт, станки, книга рецептов | можно крафтить |
| 7 | Строительство, тотем, аванпосты, ловушки, турели | можно строить |
| 8 | Бой, оружие, одежда, враги, звери, ночи | можно выживать |
| 9 | Боссы, навыки, задания, транспорт, обучение, сохранения, звук | полная игра |
| 10 | Реклама, покупки, облачные сохранения, оптимизация, релиз | релиз |

**MVP** — биомы 1–3 и боссы 1–3; данные и ассеты для 4–6 подключаются тем же кодом и закрыты флагом `mvpBiomeLimit = 3`.

## Важно

- **Звуков нет** — подбираются на шаге 9 (CC0, лицензии в `assets/audio/LICENSES.md`).
- **API площадок и версии библиотек** агент сверяет с актуальной документацией (шаги 1 и 10).
- **Плагины Capacitor** для рекламы Яндекса и платежей RuStore — от сообщества; если не подойдут, пишется свой маленький плагин на Kotlin.
- **Масштаб спрайтов** выравнивается на шаге 2 по `assets_manifest.json`.
