# Шаг 10. Яндекс Игры и RuStore: реклама, покупки, сохранения, оптимизация, релиз

## Цель

Две готовые к публикации сборки из одной веб-игры: архив для **Яндекс Игр** и подписанный AAB/APK для **RuStore** (Capacitor) — с рабочей рекламой, покупками, сохранениями, паузой и оптимизацией.

## Входные данные

- `data/balance.json → ads, iap`, GDD §16, все точки рекламы из шагов 4–9.
- Интерфейсы `PlatformServices` (шаг 1).

## ВАЖНО: сверить с документацией

API меняются. **До написания кода** агент читает актуальные документы и выписывает в `docs/PLATFORM_NOTES.md` точные методы, события и требования:

- Яндекс Игры — SDK и требования к игре: `https://yandex.ru/dev/games/doc/ru/` (SDK, реклама, данные игрока, покупки, разметка геймплея, события паузы, раздел «Требования к игре»).
- RuStore для разработчиков: `https://www.rustore.ru/help/developers/` (публикация, SDK платежей, требования к приложениям).
- Рекламная сеть для Android — по умолчанию **Yandex Mobile Ads SDK** (Рекламная сеть Яндекса), её документация и правила RuStore о рекламе.
- Плагины Capacitor: проверить свежесть и совместимость с текущей версией Capacitor. Известные плагины сообщества (не официальные, проверить перед использованием): для рекламы Яндекса — `capacitor-yandex-ads` (несколько форков на GitHub), для платежей RuStore — `capacitor-rustore-billing`. **Если плагин заброшен или не подходит — написать свой плагин Capacitor на Kotlin**, обернув официальный Android SDK (это несколько сотен строк: показ межстраничной, показ rewarded с колбэками, покупка, список покупок, подтверждение/консумирование).

## Задачи

### 10.1. Яндекс Игры — `src/platform/yandex/YandexPlatform.ts`

1. `index.html` (режим `yandex`): `<script src="/sdk.js"></script>` до бандла. `init()`: `await YaGames.init()`; все вызовы — в try/catch; без SDK — режим заглушки.
2. Готовность: после загрузки ресурсов и показа меню — `ysdk.features.LoadingAPI.ready()` (требование модерации).
3. Разметка геймплея: `GameplayAPI.start()` — вход в мир и возврат после паузы/меню/рекламы; `GameplayAPI.stop()` — меню паузы, экраны рекламы, смерти, выход в меню.
4. События площадки: подписка на `game_api_pause` / `game_api_resume` → `GameClock.pause/resume('PLATFORM')`; плюс `visibilitychange` и `blur/focus`.
5. Реклама: межстраничная — `adv.showFullscreenAdv` с колбэками закрытия и ошибки; за награду — `adv.showRewardedVideo` с колбэками открытия, награды, закрытия, ошибки. **Награда — только в колбэке награды.** Перед показом — `GameplayAPI.stop()`, пауза, звук выключен; после закрытия — всё обратно. Отказ SDK в показе (интервал площадки) — не ошибка игры.
6. Стики-баннеры — по желанию владельца, только через SDK (свои баннеры и сторонняя реклама запрещены).
7. Сохранения: данные игрока SDK (`getPlayer` → `setData`/`getData`) + локальная копия в `localStorage`; при конфликте — более новая по `savedAt`. В черновике игры в консоли включить опцию облачных сохранений. Проверить по документации ограничения размера данных и поведение для неавторизованных игроков.
8. Покупки (если включены): каталог, покупка, список купленного, **обязательное консумирование** расходуемых; «без рекламы» — постоянная. Только через SDK.
9. Язык — из окружения SDK; устройство — из `deviceInfo` (раскладка UI, ТВ не поддерживаем — отключить в консоли или поддержать стрелки пульта, решает владелец).
10. Чек-лист требований Яндекса (сверить с актуальным разделом «Требования к игре»): `index.html` в корне архива; имена файлов без пробелов и кириллицы; всё ≤ 100 МБ в распакованном виде; работа в Яндекс Браузере, Chrome, Firefox, Opera, Safari и приложении Яндекс; без сообщений про WebGL; полноэкранный режим на телефоне; управление жестами без выделения, прокрутки и swipe-to-refresh; на ПК поле до края, соотношение сторон ≤ 2:1, управление не зависит от раскладки; звук выключается при потере фокуса и во время рекламы; прогресс сохраняется после перехода по рекламе; нет зависаний при повороте экрана, сворачивании, рекламе, кнопке «Назад» в браузере.

### 10.2. RuStore — `src/platform/android/AndroidPlatform.ts` + Capacitor

1. **Реклама**: Yandex Mobile Ads через плагин (проверенный из сообщества или свой на Kotlin) — межстраничная и за награду, предзагрузка следующего показа после закрытия. Идентификаторы рекламных блоков — в конфиге сборки, не в репозитории. Пауза и выключение звука на время показа.
2. **Покупки**: SDK платежей RuStore через плагин (сообщества или свой на Kotlin): каталог, покупка, подтверждение/консумирование, восстановление покупок при запуске.
3. **Сохранения**: `@capacitor/filesystem` — файл во внутреннем хранилище + две резервные копии; запись атомарно (во временный файл → переименование).
4. **Жизненный цикл** (`@capacitor/app`): `pause` → пауза + сохранение; `resume` → возобновление; `backButton` → меню паузы, повторное «Назад» в меню → выход с подтверждением.
5. **WebView**: аппаратное ускорение, запрет зума и выделения, `android:screenOrientation="sensorLandscape"`, полный экран (иммерсивный режим), отключить отладку WebView в релизе.
6. **Сборка**: `npm run build:android` → `npx cap sync android` → подписанный AAB/APK (ключ — у владельца, вне репозитория), `versionCode` растёт с каждой сборкой, иконка и сплэш (агент делает временные из ассетов или пишет запрос в `ASSET_REQUESTS.md`).

### 10.3. Конфиг под площадку

`PlatformConfig`: скорости выживания (`balance.survival`), точки и интервалы межстраничной рекламы (`balance.ads`), набор наград, покупки, качество графики по умолчанию (браузер телефона — «среднее»: маска света в 1/4 разрешения, меньше частиц).

### 10.4. Оптимизация

1. Веб: первая загрузка — только UI, иконки, тайлы, стены, интерьер, биом 1, герой, враги, звери, эффекты; остальные атласы лениво. Vite: минификация, разделение кода сцен, сжатие ассетов. Цель — интерактивность < 10 с на 4G; замер в отчёте.
2. Рендер Phaser: один атлас на слой где возможно (батчинг), отсечение по камере, пулы объектов (снаряды, частицы, цифры урона, дроп), без создания объектов в `update()`, `setDepth` только при изменении Y.
3. Логика: пространственная сетка, ИИ дальних врагов раз в 4 тика.
4. Пресеты качества «низкое / среднее / высокое»: частицы, тени, разрешение маски света, дальность подгрузки чанков, подсветка (шейдер или простая).

### 10.5. Тестирование и релиз

1. `docs/QA_CHECKLIST.md`: первые 15 минут, смерть, ночь, кровавая ночь, боссы 1–3, каждая точка рекламы (показ, отказ сети, закрытие раньше времени), сохранение/загрузка, сворачивание в каждом состоянии, телефон в браузере, 3 Android-устройства разного класса в APK, Safari на iPhone.
2. Аналитика (`AnalyticsService`): старт, конец обучения, смерть (биом, причина), босс, реклама по точкам, покупка. Без персональных данных.
3. Режим «фото» (F9) — скрыть HUD для скриншотов страниц игры.
4. `CHANGELOG.md`, `docs/RELEASE_NOTES.md`.

- [ ] Сохранения: Яндекс — облако + локальная копия; Android — файл с резервами.
- [ ] Покупки проходят в тестовом режиме обеих площадок, расходуемые консумируются.
