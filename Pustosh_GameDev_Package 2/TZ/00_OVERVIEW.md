# 00. Общее техническое задание

## 1. Продукт

**«Пустошь»** — 2D-выживание в открытом мире после катастрофы, вид сверху под углом (каждый объект показывает верх и переднюю сторону, как в классических top-down RPG). Смесь Minecraft (строй где угодно, разбирай мир на ресурсы), Terraria (боссы открывают новые биомы) и 7 Days to Die (руины, лут, ночные орды).

- Платформы: **Яндекс Игры** (браузер на ПК и телефоне) и **RuStore** (Android). **Одна кодовая база — веб-игра.** Android-версия — та же веб-игра внутри нативной оболочки Capacitor.
- Монетизация: реклама (межстраничная + за награду) и покупки. Подробно — GDD §16 и шаг 10.
- Аудитория: 12+, без крови и жестокости.
- Язык интерфейса: русский; все строки — через файл локализации.

## 2. Стек

| Что | Выбор | Зачем |
| --- | --- | --- |
| Язык | **TypeScript** (strict) | один язык для веба и Android-оболочки; типы ловят ошибки данных |
| Движок | **Phaser** — последняя стабильная версия ветки 3.x | самый массовый 2D-движок для браузера, тайлы, атласы, камеры, WebGL с откатом на Canvas, огромное число примеров |
| Сборка | **Vite** | быстрый dev-сервер, сборка с режимами `yandex` / `android` / `dev` |
| Android-оболочка | **Capacitor** (актуальная стабильная версия) | заворачивает веб-сборку в Android-приложение, даёт плагины к нативным SDK |
| Нативные плагины | официальные/сообщества плагины Capacitor; при их отсутствии — **свой плагин на Kotlin** | реклама и платежи RuStore на Android |
| Проверка данных | **zod** | схемы для `data/*.json`, понятные ошибки |
| Тесты | **Vitest** | логика (`src/core`) тестируется без браузера и без Phaser |
| Качество кода | ESLint + Prettier | единый стиль, запрет импорта Phaser в `src/core` |

**Про версию Phaser.** Phaser 4 уже вышел, но он моложе, и примеров под него меньше. По умолчанию берём **последнюю 3.x** (её лучше знают и нейросети, и сообщество). Переход на 4 — только по решению владельца после отдельной проверки.

**Перед началом агент обязан** проверить актуальные стабильные версии Phaser, Vite, Capacitor и выбранных плагинов (npm, официальные сайты) и записать их в `docs/VERSIONS.md`.

## 3. Архитектура

```
pustosh/
├─ src/
│  ├─ core/            # чистый TypeScript: НЕ импортирует Phaser и браузерные API
│  │  ├─ data/         # zod-схемы, загрузка и валидация data/*.json, Registry
│  │  ├─ world/        # мир: чанки, генерация по сиду, клетки, объекты, строительная сетка
│  │  ├─ ecs/          # сущности и компоненты (Position, Health, Inventory, AI, Harvestable…)
│  │  ├─ systems/      # Movement, Survival, Harvest, Craft, Build, Combat, AI, Spawn, DayNight, Progression
│  │  ├─ save/         # модель сохранения с версиями и миграциями
│  │  ├─ config/       # Balance, PlatformConfig, фичефлаги
│  │  └─ util/         # GameClock, RNG по сиду, шум, математика
│  ├─ game/            # Phaser: сцены, рендер, ввод, звук, UI, риг, эффекты
│  │  ├─ scenes/       # Boot, Preload, MainMenu, World, UI (поверх World), Pause, debug-сцены
│  │  ├─ render/       # TileLayer, ObjectLayer (Y-сортировка), Lighting, Highlight, Particles
│  │  ├─ rig/          # RigDef, RigInstance, AnimationPlayer, RigEditor (debug)
│  │  ├─ ui/           # HUD, Hotbar, Inventory, CraftBook, BuildMenu, Skills, Map, Dialogs
│  │  └─ input/        # VirtualJoystick, Keyboard+Mouse, InputMapper → команды
│  ├─ platform/
│  │  ├─ PlatformServices.ts   # интерфейсы (окончательные, см. шаг 1)
│  │  ├─ yandex/               # YandexPlatform — SDK Яндекс Игр
│  │  ├─ android/              # AndroidPlatform — Capacitor-плагины (реклама, RuStore-платежи, файлы, жизненный цикл)
│  │  └─ dev/                  # DevPlatform — заглушки для локальной разработки
│  └─ main.ts          # выбор платформы по import.meta.env.VITE_PLATFORM, запуск Phaser
├─ public/
│  ├─ atlases/         # результат упаковки ассетов (шаг 2)
│  └─ data/            # копия data/*.json (+ созданные позже файлы)
├─ tools/              # pack-assets.ts, validate-data.ts (запуск через tsx/node)
├─ tests/              # Vitest
├─ android/            # генерирует Capacitor; правки — только через плагины и конфиг
└─ capacitor.config.ts
```

Правила:

1. **`src/core` не знает про Phaser и браузер.** Нарушение ловит ESLint (`no-restricted-imports` для `phaser`, запрет `window`/`document` в core). Логика тестируется в Vitest без окна.
2. **Фиксированный шаг логики**: 20 тиков в секунду (`TICK = 50 мс`), рендер с интерполяцией. Время в логике — только тики и игровые секунды; `Date.now()` и `performance.now()` в `core` запрещены (кроме `GameClock`).
3. **Детерминированность мира**: генерация зависит только от сида и координат чанка. Свой RNG по сиду (`mulberry32`/`xoshiro`), `Math.random()` в `core` запрещён.
4. **Данные, а не код**: числа баланса, рецепты, дропы, размеры — только в `data/*.json`.
5. **Платформенные различия — только через `PlatformServices` и `PlatformConfig`.** В игровом коде нет `if (platform === 'yandex')`. Выбор реализации — в `main.ts` по переменной сборки.
6. **Пауза**: единая точка `GameClock.pause(reason)` / `resume(reason)` с набором причин (`AD`, `MENU`, `TAB_HIDDEN`, `PLATFORM`, `DIALOG`). Игра идёт, только когда набор пуст. Звук глушится при любой паузе.
7. **Сохранения версионируются** (`saveVersion`), есть миграции. Автосохранение раз в 60 с, при выходе в меню, сворачивании, скрытии вкладки.
8. **Логирование** через один `log` с уровнями; в релизе — только warn/error.
9. **TypeScript strict**, без `any` в `core` (в обёртках SDK допускается с комментарием).

## 4. Сборки

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер Vite, платформа `dev` (заглушки), открыть в браузере ПК или телефона в локальной сети |
| `npm run build:yandex` | сборка с `VITE_PLATFORM=yandex`, относительные пути (`base: './'`), `<script src="/sdk.js">` в `index.html`, архив `dist-yandex.zip` для консоли Яндекса |
| `npm run build:android` | сборка с `VITE_PLATFORM=android` (без SDK Яндекса) → `npx cap sync android` → подписанный AAB/APK через Gradle Android-проекта |
| `npm test` | Vitest для `src/core` |
| `npm run pack-assets` | упаковка атласов (шаг 2) |
| `npm run validate-data` | валидация `data/*.json` (шаг 2) |

## 5. Координаты и размеры

- Тайл = **64 px** при масштабе 1x. Мир: 512×512 тайлов, чанк 32×32 тайла.
- Ось Y вниз. Позиция объекта = точка основания (origin 0.5, 1.0), по ней идёт Y-сортировка (`setDepth(y)`).
- Камера Phaser: следование за героем, зум 0.75–1.25, ограничение краями мира.
- Масштабирование игры: `Phaser.Scale.FIT` или `RESIZE` с логическим разрешением 1280×720; на телефоне в кадре ~11×6 тайлов, на ПК ~16×9. **Требование Яндекса:** на ПК длинная сторона игрового поля не больше чем в 2 раза длиннее короткой, поле растягивается до края.
- Android: только альбомная ориентация, полный экран.

## 6. Ввод

| Действие | Телефон | ПК (Яндекс) |
| --- | --- | --- |
| Движение | виртуальный стик слева | WASD / стрелки (по `event.code`, не зависит от раскладки) |
| Действие (удар / добыча / подобрать / открыть) | одна «умная» кнопка | ЛКМ в сторону курсора, E |
| Перекат | кнопка | Пробел |
| Строить | кнопка | B |
| Инвентарь | кнопка рюкзака | Tab / I |
| Пояс 1–6 | тап по слоту | 1–6, колесо |
| Карта | кнопка | M |
| Пауза | кнопка | Esc |

На телефоне в браузере обязательно: запрет выделения текста и контекстного меню на долгий тап, запрет прокрутки страницы и «потяни, чтобы обновить» (CSS `touch-action: none`, `user-select: none`, `overscroll-behavior: none`), управление одной рукой для основных действий.

## 7. Определения

- **Тир** — уровень материала/инструмента 0–6 (GDD §6).
- **Игровые сутки** — 720 c реального времени (день 480 c, ночь 240 c).
- **Кровавая ночь** — каждая 7-я ночь.
- **База** — область вокруг «Тотема базы» (`base_core`).
- **MVP** — биомы 1–3, боссы 1–3; остальное закрыто флагом `mvpBiomeLimit = 3`.

## 8. Общие критерии качества (на каждом шаге)

- `npm run build:yandex` и `npm run build:android` проходят без ошибок TypeScript.
- `npm test` зелёный, ESLint без ошибок.
- ПК — 60 FPS; телефон среднего класса в браузере и в APK — ≥ 45 FPS в сцене с 40 врагами в кадре (с шага 8).
- Ни одной ссылки на ассет мимо `assets_manifest.json`, ни одного числа баланса вне `data/`.
- Каждый шаг заканчивается записью в `CHANGELOG.md`: сделано, отложено, известные проблемы.

## 9. Чего не делать

- Не генерировать и не перерисовывать картинки — использовать `assets/`. Недостающее делать кодом и записывать в `ASSET_REQUESTS.md`.
- Не использовать спрайты со статусом `replaced`.
- Не добавлять мультиплеер, чат, сторонние трекеры и внешние ссылки (запрещено правилами Яндекса).
- Не тянуть тяжёлые зависимости: каждый МБ — время загрузки. Весь веб-билд — не больше 100 МБ в распакованном виде (лимит Яндекса), цель — намного меньше.
