# Шаг 2. Ассет-пайплайн и загрузка данных

## Цель

Все спрайты из `assets/` попадают в игру в правильном размере через атласы, а все `data/*.json` загружаются в типизированные модели и проверяются валидатором. В игре есть отладочная **галерея ассетов**.

## Входные данные

- `assets/` (723 PNG), `assets_manifest.json`, `TZ/ASSETS.md`.
- `data/*.json`: items, stations, recipes, building, defense, enemies, bosses, biomes, vehicles, skills, balance, rigs.

## Задачи

### 2.1. Пайплайн ассетов (`tools/` + задача Gradle)

1. Скопировать `assets/` и `assets_manifest.json` в `tools/source_assets/` (исходники не трогать).
2. Написать инструмент (Kotlin-скрипт или Gradle-задача `packAssets`), который:
   - читает манифест, **пропускает `status: replaced`**;
   - для каждого спрайта вычисляет итоговый размер по `scaleMode`/`targetPx` и умножает на **2** (хранение в 2x для чётких экранов; в игре рисуется в 1x-координатах);
   - для тайлов (`scaleMode: exact`) — 128×128 (2x от 64), без отступов, с повтором края на 2 px (extrude), чтобы не было швов при фильтрации;
   - для стен (`special`) — лицо стены 128×96, верх и пол 128×128;
   - для рига (`rig`) — не масштабирует: части пакуются в исходном размере, масштаб применяет риг;
   - режет составные файлы из `ASSETS.md §6` (язык/мешок жабы — по горизонтальной линии на 25% высоты);
   - пакует в атласы до 2048×2048 по группам: `ui`, `icons`, `tiles`, `walls`, `interior_defense`, `biome1`…`biome6`, `hero`, `enemies`, `animals`, `bosses`, `vehicles`, `effects`; отступ между спрайтами 2 px, extrude 1 px;
   - пишет для каждого атласа `.png` + описание регионов (формат, который KorGE читает нативно, или свой JSON) + общий `asset_index.json`: `assetId → (atlas, region, pivot, logicalSize)`.
3. **Pivot:** `bottom_center` → (0.5, 1.0), `center` → (0.5, 0.5), `top_left` → (0, 0). Значение хранится в `asset_index.json`.
4. Веб-оптимизация: атласы PNG, сжатие без потерь; итоговый размер ресурсов первой загрузки (UI + иконки + тайлы + биом 1 + герой + враги + эффекты) — записать в отчёт. Атласы биомов 2–6 и боссов грузятся лениво при подходе к биому.

### 2.2. Загрузка данных (`core/data`)

1. Модели `@Serializable` под каждый файл: `ItemDef`, `StationDef`, `RecipeDef`, `BuildingDef` (+ `MaterialDef`), `DefenseDef`, `EnemyDef`, `BossDef`, `BiomeDef` (+ `WorldObjectDef`, `HarvestDef`, `LootContainerDef`), `VehicleDef`, `SkillsDef`, `BalanceDef`, `RigDef`. Неизвестные поля игнорировать (`ignoreUnknownKeys = true`), обязательные поля — без значений по умолчанию.
2. Пути к картинкам в данных (`assets/...png`) преобразуются в `assetId` манифеста (`folder.name`) при загрузке.
3. **Валидатор** (`DataValidator`), запускается при старте в debug и в юнит-тесте:
   - все ссылки на предметы в рецептах, дропах, стоимостях построек существуют;
   - все станки рецептов существуют; все `requiresSkill` — существующие ветка+уровень;
   - все картинки существуют в `asset_index.json` и не `replaced`;
   - у каждого босса есть трофей-предмет; у каждого биома есть босс и тайлы;
   - нет циклов крафта, где предмет нужен для собственного производства на том же станке;
   - печатает отчёт: N ошибок, N предупреждений.
4. `Registry` — единая точка доступа: `items[id]`, `recipesByStation[station]`, `objectsByBiome[n]` и т.д.
5. Локализация: `strings_ru.json` в ресурсах; имена из данных (`name_ru`) — по умолчанию; ключи UI — через `Strings.get("ui.play")`.

### 2.3. Галерея ассетов (debug-сцена)

Сцена `AssetGalleryScene` (F2 на ПК): вкладки по группам атласов, сетка спрайтов в логическом размере на фоне тайла травы, подпись `assetId`, отображение pivot точкой, переключатель фона (светлый/тёмный/шахматка). Отдельная вкладка «Тайлы» — каждый тайл повторён 4×4, чтобы видеть швы. Вкладка «Стены» — пример комнаты 4×3 из каждого материала.

## Критерии приёмки

- [ ] `./gradlew packAssets` создаёт атласы и `asset_index.json`; повторный запуск без изменений не пересобирает (кэш по хешу).
- [ ] В атласах нет спрайтов со статусом `replaced`.
- [ ] В галерее все группы отображаются, нет розовой/синей каймы на тёмном фоне (кроме оговорённых в ASSETS §6), тайлы повторяются без видимых швов.
- [ ] Галерея: дерево выше героя-эталона (`hero.ref_idle`) примерно в 2 раза, машина шире героя в 1.5–2 раза, ящик ниже пояса героя — масштаб на глаз правдоподобен. Отклонения записать и исправить в `targetPx` манифеста.
- [ ] Валидатор: 0 ошибок на текущих данных; юнит-тест `DataValidatorTest` проходит; искусственно испорченный рецепт даёт ошибку.
- [ ] Отчёт о размере первой загрузки веб-билда в `docs/ASSET_REPORT.md`.

## Не делать на этом шаге

Мир, логику предметов.

## Промпт для ИИ

> Выполни шаг 2 из `TZ/STEP_02_assets_and_data.md`. Прочитай `TZ/ASSETS.md` и `assets_manifest.json`. Сделай пайплайн упаковки атласов с ресайзом по `targetPx` (хранение 2x), pivot из манифеста, пропуском `replaced` и разрезанием составных файлов; модели и загрузчик всех `data/*.json`, валидатор и галерею ассетов. Ничего не меняй в `assets/` и `data/` — если нашёл ошибку в данных, опиши её в отчёте. В конце пройди «Критерии приёмки» и приложи скриншоты галереи (вкладки: иконки, биом 1, тайлы, стены).
