# Шаг 10. Яндекс Игры и RuStore: реклама, покупки, сохранения, оптимизация, релиз

## Цель

Две готовые к публикации сборки из одной кодовой базы: веб-архив для Яндекс Игр и AAB/APK для RuStore — с рабочей рекламой, покупками, сохранениями, паузой и оптимизацией.

## Входные данные

- `data/balance.json → ads, iap`, GDD §16, все точки рекламы из шагов 4–9.
- Интерфейсы `PlatformServices` (шаг 1).

## ВАЖНО: сверить с документацией

API площадок меняются. **До написания кода** агент открывает и читает актуальные документы и выписывает в `docs/PLATFORM_NOTES.md` точные названия методов, событий и требования:

- Яндекс Игры, SDK и требования к играм: `https://yandex.ru/dev/games/doc/ru/` (разделы: SDK, реклама, данные игрока, покупки, разметка геймплея, события паузы, требования к игре).
- RuStore для разработчиков: `https://www.rustore.ru/help/developers/` (публикация, SDK платежей, требования).
- Выбранная рекламная сеть для Android (например, Yandex Mobile Ads SDK или VK Ads) — её документация и правила RuStore по рекламе.

Ниже — ожидаемая схема; если документация расходится, права документация, расхождение записать.

## Задачи

### 10.1. Яндекс Игры (`platform/js/YandexPlatform`)

1. `index.html`: `<script src="/sdk.js"></script>` до бандла игры. Инициализация: `YaGames.init()` → объект SDK; обёртки через `external`/`dynamic` Kotlin/JS, все вызовы в try/catch, отсутствие SDK — режим заглушки.
2. Загрузка: после окончания загрузки ресурсов и показа меню — `ysdk.features.LoadingAPI.ready()` (сообщает, что игра готова; требование модерации).
3. Разметка геймплея: `GameplayAPI.start()` при входе в мир и после каждой паузы/меню; `GameplayAPI.stop()` при открытии меню паузы, экранов с рекламой, смерти, выходе в меню.
4. События платформы: подписка на паузу и возобновление SDK (`game_api_pause` / `game_api_resume`) → `GameClock.pause(PLATFORM)` / `resume(PLATFORM)`; плюс `visibilitychange`.
5. Реклама: межстраничная — `adv.showFullscreenAdv` с колбэками закрытия и ошибки; за награду — `adv.showRewardedVideo` с колбэками открытия, награды, закрытия, ошибки. Награда выдаётся **только** в колбэке награды. Перед показом — `GameplayAPI.stop()` и пауза + выключение звука; после закрытия — возобновление. Интервал межстраничной — из конфига; SDK может сам отказать в показе — это не ошибка игры.
6. Сохранения: данные игрока SDK (`getPlayer` → `setData`/`getData`), с локальной копией в `localStorage` как запасной; при конфликте — более новое по `savedAt`. Неавторизованный игрок — тоже сохраняется (проверить в документации поведение).
7. Покупки (если владелец включит): каталог, покупка, проверка купленного, потребление расходуемых; «без рекламы» — постоянная покупка.
8. Язык: из окружения SDK; устройство: из `deviceInfo` (для раскладки UI).
9. Требования модерации, которые проверить отдельно: звук выключается при паузе и рекламе; игра не реагирует на ввод во время рекламы; нет внешних ссылок; корректная работа на телефоне в браузере (тач, без скролла страницы, без контекстного меню на долгий тап); полноэкранный режим/ресайз окна; время до интерактивности.
10. Сборка: `build/web` → zip для загрузки в консоль разработчика; проверить, что все пути относительные.

### 10.2. RuStore (`platform/android/RuStorePlatform`)

1. Реклама: интеграция выбранной сети (межстраничная + за награду), идентификаторы блоков — в `local.properties`/секретах, не в репозитории. Пауза игры на время показа.
2. Покупки: RuStore SDK платежей (проверка подписи/статуса по документации), продукты из `balance.iap`.
3. Сохранения: файл во внутреннем хранилище + резервная копия (две последние версии); экспорт/импорт сохранения в файл (по желанию).
4. Жизненный цикл: `onPause` → пауза + сохранение; `onResume` → возобновление; кнопка «Назад» → меню паузы, повторное нажатие в меню → выход с подтверждением.
5. Сборка: подписанный AAB/APK, `versionCode` растёт с каждой сборкой, иконка приложения (агент делает из `ui/marker_boss` или по запросу владельца — `ASSET_REQUESTS.md`).

### 10.3. Конфиг под площадку

`PlatformConfig`: скорости выживания (`balance.survival`), точки и интервалы межстраничной рекламы (`balance.ads`), набор наград, покупки, качество графики по умолчанию (веб на телефоне — «среднее»: свет в 1/4 разрешения, меньше частиц).

### 10.4. Оптимизация

1. Веб: первая загрузка — только UI, иконки, тайлы, биом 1, герой, враги биома 1, эффекты; остальное лениво. Сжатие бандла, удаление неиспользуемого кода. Цель — интерактивность < 10 с на 4G (замерить, записать в отчёт).
2. Рендер: батчинг по атласам, отсечение невидимого, пул частиц и снарядов, без аллокаций в игровом цикле (профилировщик).
3. Логика: пространственная сетка для запросов, ИИ далёких врагов обновляется раз в 4 тика.
4. Пресеты качества: «низкое / среднее / высокое» (частицы, тени, разрешение маски света, дальность подгрузки чанков).

### 10.5. Тестирование и релиз

1. Чек-лист ручного теста `docs/QA_CHECKLIST.md`: первые 15 минут, смерть, ночь, кровавая ночь, каждый босс 1–3, каждая точка рекламы (межстраничная и за награду, отказ сети, закрытие раньше времени), сохранение/загрузка, сворачивание в каждом состоянии, телефон в браузере, Android 3 устройства разных классов.
2. Аналитика (через `AnalyticsService`): старт игры, конец обучения, смерть (биом, причина), победа над боссом, показ/закрытие рекламы по точкам, покупка. Никаких персональных данных.
3. Материалы для страниц игры (владелец генерирует сам): иконка, обложки, скриншоты — агент делает режим «фото» (скрыть HUD, F9) для скриншотов.
4. Финальный `CHANGELOG.md` и `docs/RELEASE_NOTES.md`.

## Критерии приёмки

- [ ] Веб-сборка в черновике Яндекс Игр: SDK инициализируется, «готовность» отправляется, разметка геймплея корректна, пауза по событиям платформы работает.
- [ ] Каждая точка рекламы из GDD §16 работает на обеих площадках; награда выдаётся только после досмотра; игра на паузе и без звука во время показа.
- [ ] Сохранения: облако Яндекса + локальная копия; Android — файл с резервом; переустановка/очистка — понятное поведение.
- [ ] Чек-лист `QA_CHECKLIST.md` пройден, баги записаны и закрыты.
- [ ] Отчёт о производительности и размерах сборок в `docs/PERF_REPORT.md`.
