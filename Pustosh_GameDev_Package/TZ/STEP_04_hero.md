# Шаг 4. Герой: управление, анимация по частям, выживание, смерть

## Цель

Живой герой: ходит, бегает, перекатывается, анимирован «куклой» из частей, тратит голод, жажду, выносливость, мёрзнет и греется, умирает и возрождается. Готов редактор рига для калибровки частей.

## Входные данные

- `assets/characters/hero/*`, `data/rigs.json → humanoid`, `data/balance.json → player, survival`.
- GDD §4, OVERVIEW §5 (ввод).

## Задачи

### 4.1. Ввод (`game/input`)

1. `InputMapper` переводит устройства в команды: `MoveVector`, `Action(target)`, `Dodge`, `ToggleBuild`, `OpenInventory`, `SelectSlot(n)`, `OpenMap`, `Pause`.
2. Телефон: плавающий стик слева (основание `ui/joystick_base`, ручка `ui/joystick_knob`; появляется там, где палец коснулся левой половины экрана), справа кнопки `ui/btn_action|btn_attack|btn_dodge|btn_build`. Иконка «умной» кнопки меняется по цели: рука — подобрать/открыть, кулак — ударить, иконка инструмента — добыть.
3. ПК: WASD/стрелки, мышь задаёт направление атаки, ЛКМ — действие, E, Пробел, B, Tab/I, 1–6, колесо, M, Esc.

### 4.2. Движение (`core/systems/Movement`)

Скорость `player.speedTilesPerSec`, бег ×`sprintMul` (тратит выносливость 10/с), перекат на 1.5 тайла за 0.35 с с неуязвимостью `dodgeIFramesSec`, стоимость `dodgeStamina`. Замедления от местности: вода/грязь ×0.6, снег ×0.85 (без транспорта). Коллизии из шага 3.

### 4.3. Риг и анимации (`game/rig`)

1. `RigDef` из `data/rigs.json → humanoid`: кости, родитель, спрайт, pivot (доли от размера части), attach (доли от `bodyHeightPx`), z, тинт для дальних конечностей.
2. Начальный масштаб каждой части — по `partLengthFrac` и длинной стороне PNG (формула `scaleRule`). Дальняя рука/нога — те же спрайты с тинтом `#9A9A9A`.
3. **Редактор рига** (debug, F6): выбор персонажа (герой, любой враг, зверь), выбор кости, перетаскивание pivot и attach мышью, колесо — масштаб, Q/E — поворот покоя, наложение полупрозрачного эталона `ref_idle` для сравнения, кнопка «Сохранить» → `rigs_tuned/<id>.json` (переопределяет `rigs.json`). Эти файлы — часть данных проекта.
4. `AnimationPlayer`: ключевые кадры углов/смещений с интерполяцией (ease in-out), смешивание переходов 0.1 с. Анимации из `rigs.json → animations`: idle, walk, run, attack_slash/blunt/pierce, shoot, gather, dodge, hurt, blink, death. «Хит-кадр» атаки отправляет событие в логику (шаг 5/8).
5. Голова: `head_neutral` по умолчанию, `head_hurt` 0.3 с после урона, `head_blink` случайно раз в 3–6 с на 0.12 с; при надетом головном уборе — `head_helmet|head_gasmask|head_furhat` (поле `heroHead` предмета).
6. Предмет в руке: иконка экипированного предмета на кости `held_item`, масштаб 0.45 роста, поворот вместе с рукой.
7. Разворот влево — `scaleX = -1` у корня; направление — по вектору движения или курсору (ПК).
8. **Запасной режим (обязателен как fallback)**: если для персонажа нет откалиброванного рига — рисовать `ref_idle`, шаг чередует `ref_walk`/`ref_idle` каждые 0.18 с с подпрыгиванием 2 px. Переключатель в настройках debug.

### 4.4. Выживание (`core/systems/Survival`)

1. Показатели и скорости из `balance.survival.<platform>`; жажда ×1.5 в пустыне днём.
2. Температура: базовая от биома и времени суток (пригород 0, болото 0, город 0, пустыня день +3/ночь −1, тундра −4/−6, эпицентр 0), минус `coldRes`/`heatRes` одежды, плюс костёр (+4 в радиусе 3 тайлов), минус ночь. Значение вне диапазона [−2, +2] наносит урон `coldDmgPerSec` и замедляет на 15%.
3. Радиация: зоны (данные биома 6 + поля вокруг светящихся врагов) повышают значение; максимум HP = 100 − радиация.
4. Состояния: кровотечение, отравление, инфекция, перелом (GDD §4) с таймерами; иконки в HUD.
5. HUD (`ui/bar_frame` + `bar_fill_red` тинтуется под показатель; иконки `ui/icon_*`): здоровье — полоса, остальные — иконка с кольцом-заполнением; мигание при < 20%.

### 4.5. Смерть и возрождение

1. HP = 0 → анимация смерти → затемнение → экран «Вы погибли» с кнопками «Возродиться» и «Возродиться на месте (реклама)».
2. Перед экраном — **точка межстраничной рекламы `death`** (`ads.canShowInterstitial()` → показать; пауза на время).
3. Возрождение у последней кровати/спальника, иначе в бункере старта. Содержимое инвентаря (не экипировка) — в объект «рюкзак погибшего» (`world/interior/dead_backpack`) на месте смерти, время жизни `deathBackpackLifetimeSec`, метка на карте. Полное здоровье −30% (кроме рекламного возрождения).

## Критерии приёмки

- [ ] Управление работает на ПК и телефоне (проверить в браузере телефона и в APK).
- [ ] Риг героя откалиброван в редакторе: в idle силуэт совпадает с `ref_idle` (наложение), при ходьбе нет щелей в суставах.
- [ ] Все анимации из списка проигрываются; моргание и гримаса боли видны.
- [ ] Fallback-режим включается переключателем и выглядит прилично.
- [ ] Голод и жажда падают с заданной скоростью (юнит-тест на 10 игровых минут); у костра ночью в тундре температура не уходит в урон.
- [ ] Смерть → реклама-заглушка → экран → возрождение у кровати; рюкзак погибшего лежит на месте смерти и исчезает через 20 мин игрового времени.
- [ ] Откалиброванные риги сохранены в `rigs_tuned/hero.json`.
