# 00. Общее техническое задание

## 1. Продукт

**«Пустошь»** — 2D-выживание в открытом мире после катастрофы, вид сверху под углом (каждый объект показывает верх и переднюю сторону, как в классических top-down RPG). Смесь Minecraft (строй где угодно, разбирай мир на ресурсы), Terraria (боссы открывают новые биомы) и 7 Days to Die (руины, лут, ночные орды).

- Платформы: **Яндекс Игры** (браузер на ПК и телефоне) и **RuStore** (Android). Одна кодовая база, отличаются только платформенные сервисы и конфиг.
- Монетизация: реклама (межстраничная + за награду) и покупки. Подробно — GDD §12 и шаг 10.
- Аудитория: 12+, без крови и жестокости (раны не рисуются, только «гниль» цветом и рваная одежда).
- Язык интерфейса: русский; все строки — через файл локализации, чтобы позже добавить английский.

## 2. Стек

| Что | Выбор | Почему |
| --- | --- | --- |
| Язык | Kotlin (Multiplatform) | разработчик пишет на Kotlin |
| Движок | **KorGE** (2D-движок на Kotlin Multiplatform) | один код → браузер (Kotlin/JS) + Android + десктоп для отладки |
| Данные | JSON + kotlinx.serialization | весь контент в `data/*.json`, код его только читает |
| Тесты | kotlin.test в `commonTest` | логика (крафт, инвентарь, урон, сохранения) покрывается юнит-тестами без движка |
| Сборка | Gradle (Kotlin DSL) | стандарт KorGE |

**Перед началом агент обязан** проверить актуальную стабильную версию KorGE и её способ подключения таргетов (`https://docs.korge.org`). Если веб-сборка KorGE в текущей версии нестабильна, остановиться и сообщить владельцу; запасной вариант — libGDX + KTX (веб через TeaVM/GWT-бэкенд), решение принимает владелец.

## 3. Архитектура

```
pustosh/
├─ core/            # чистый Kotlin (commonMain), без зависимостей от движка
│  ├─ data/         # модели JSON (ItemDef, RecipeDef, EnemyDef...) + загрузчик и валидатор
│  ├─ world/        # мир: чанки, генерация по сиду, клетки, объекты, сетка строительства
│  ├─ ecs/          # сущности и компоненты (Position, Health, Inventory, AI, Harvestable...)
│  ├─ systems/      # логика: Movement, Survival, Harvest, Craft, Build, Combat, AI, Spawn, DayNight, Progression
│  ├─ save/         # модель сохранения (версионируемая), сериализация
│  └─ config/       # Balance, PlatformConfig (yandex/rustore/desktop), фичефлаги
├─ game/            # KorGE: сцены, рендер, ввод, звук, UI, анимация ригов, эффекты
│  ├─ scenes/       # Boot, Loading, MainMenu, World, Pause
│  ├─ render/       # TileLayer, ObjectLayer (Y-сортировка), LightingOverlay, Highlight, Particles
│  ├─ rig/          # RigDef, RigInstance, AnimationPlayer, RigEditor (debug)
│  ├─ ui/           # HUD, Hotbar, Inventory, CraftBook, BuildMenu, Skills, Map, Dialogs
│  └─ input/        # Joystick (тач), Keyboard+Mouse, InputMapper → команды
├─ platform/        # интерфейс PlatformServices + реализации
│  ├─ common/       # interface PlatformServices, AdsService, SaveService, PurchaseService, Analytics
│  ├─ js/           # YandexPlatform (вызовы ysdk через external/js)
│  ├─ android/      # RuStorePlatform (реклама, RuStore Billing, локальные сохранения)
│  └─ jvm/          # DesktopStub (реклама = диалог-заглушка 2 c, сохранения в файл)
└─ tools/           # пайплайн ассетов (атласы), валидатор данных
```

Правила:

1. **`core` не знает про движок.** Логика тестируется без окна. Рендер только читает состояние `core`.
2. **Фиксированный шаг логики**: 20 тиков в секунду (`TICK = 50 мс`), рендер с интерполяцией. Вся логика времени — в тиках или игровых секундах, никаких `System.currentTimeMillis` в логике.
3. **Детерминированность мира**: генерация зависит только от сида (`balance.world.seed`) и координат чанка. Один сид = одинаковый мир на всех платформах.
4. **Данные, а не код**: числа баланса, рецепты, дропы, размеры — только в `data/*.json`. Хардкод числа в коде = ошибка ревью.
5. **Платформенные различия — только через `PlatformServices` и `PlatformConfig`**. В игровом коде нет `if (isYandex)`.
6. **Пауза**: единая точка `GameClock.pause(reason)` / `resume(reason)` с набором причин (`AD`, `MENU`, `TAB_HIDDEN`, `PLATFORM`). Игра идёт, только когда набор пуст. Звук глушится при любой паузе.
7. **Сохранения версионируются** (`saveVersion`), есть миграции. Автосохранение раз в 60 с и при выходе в меню/сворачивании.
8. **Логирование** через один `Log` с уровнями; в релизе — только WARN/ERROR.

## 4. Координаты и размеры

- Тайл = **64 px** при масштабе 1x. Мир: 512×512 тайлов, чанк 32×32 тайла.
- Ось Y вниз. Позиция объекта = точка его основания (pivot bottom_center), по ней идёт Y-сортировка.
- Камера: ортографическая, вид сверху; глубина имитируется только порядком отрисовки и ракурсом спрайтов.
- Масштаб экрана: на телефоне в кадре ~11×6 тайлов (альбомная ориентация), на ПК ~16×9. Зум колёсиком/щипком в пределах 0.75–1.25.
- Ориентация на Android: только альбомная.

## 5. Ввод

| Действие | Телефон | ПК (Яндекс) |
| --- | --- | --- |
| Движение | виртуальный стик слева | WASD / стрелки |
| Действие (удар / добыча / подобрать / открыть) | одна «умная» кнопка, иконка зависит от цели | ЛКМ — удар/добыча в сторону курсора, E — подобрать/открыть |
| Перекат | кнопка | Пробел |
| Строить | кнопка → режим строительства | B |
| Инвентарь | кнопка рюкзака | Tab / I |
| Пояс 1–6 | тап по слоту | 1–6, колесо |
| Карта | кнопка | M |
| Пауза | кнопка | Esc |

Определение устройства: на Яндексе — через SDK (`deviceInfo`), иначе по наличию тача. Раскладка UI переключается автоматически.

## 6. Определения

- **Тир** — уровень материала/инструмента 0–6 (GDD §6). Инструмент добывает ресурс, если `tool.harvestTier >= object.harvest.minTier`.
- **Игровые сутки** — 720 c реального времени (день 480 c, ночь 240 c).
- **Кровавая ночь** — каждая 7-я ночь, орда идёт на базу игрока.
- **База** — область вокруг «Тотема базы» (`base_core`).
- **MVP** — биомы 1–3, боссы 1–3, весь остальной контент закрыт флагом `mvpBiomeLimit`.

## 7. Общие критерии качества (на каждом шаге)

- Проект собирается тремя таргетами без предупреждений компилятора уровня error.
- Юнит-тесты `core` проходят (`./gradlew :core:allTests` или аналог).
- На ПК 60 FPS, на средних Android-устройствах ≥ 45 FPS в сцене с 40 врагами в кадре (с шага 8).
- Ни одной ссылки на ассет вне `assets_manifest.json`; ни одного числа баланса вне `data/`.
- Каждый шаг заканчивается коротким `CHANGELOG.md`-записью: что сделано, что отложено, известные проблемы.

## 8. Чего не делать

- Не перерисовывать и не генерировать новые картинки — используем то, что есть в `assets/`. Если чего-то не хватает, делать кодом (тинт, масштаб, фигуры, частицы) и записывать в `ASSET_REQUESTS.md`.
- Не использовать спрайты со статусом `replaced` из манифеста.
- Не добавлять сетевой мультиплеер, внутриигровой чат, генерацию контента нейросетью.
- Не тянуть тяжёлые зависимости в веб-билд (каждый МБ влияет на загрузку в Яндексе).
