# «Пустошь» — пакет для разработки игры

Версия пакета: 1.0 · 27.10.2026

Это полный пакет для разработки 2D-игры на выживание в открытом постапокалиптическом мире с видом сверху. Код пишется на Kotlin, одна кодовая база собирается в два билда: **Яндекс Игры** (браузер) и **RuStore** (Android).

Пакет рассчитан на то, чтобы отдавать его нейросети-разработчику (ИИ-агенту) по шагам. Внутри есть всё: ТЗ из 10 шагов, дизайн игры, готовые игровые данные в JSON и 723 нарезанных спрайта с прозрачным фоном.

## Что внутри

| Путь | Что это |
| --- | --- |
| `START_HERE.md` | этот файл: как пользоваться пакетом |
| `TZ/00_OVERVIEW.md` | общее ТЗ: стек, архитектура, структура проекта, правила кода, определения |
| `TZ/GDD.md` | дизайн игры: цикл, мир, биомы, враги, боссы, крафт, строительство, прогрессия, реклама |
| `TZ/ASSETS.md` | каталог ассетов, правила масштаба и привязки, известные дефекты |
| `TZ/STEP_01 … STEP_10` | 10 шагов разработки: задачи, классы, критерии приёмки, готовый промпт для ИИ |
| `data/*.json` | игровые данные: предметы, рецепты, станки, постройки, защита, враги, боссы, биомы, транспорт, навыки, баланс, скелеты |
| `assets_manifest.json` | список всех 723 спрайтов: путь, размер, исходный лист, статус, целевой размер в игре, точка привязки |
| `assets/` | нарезанные спрайты (PNG с альфой), разложены по папкам |
| `source_sheets/` | исходные листы из ChatGPT, из которых нарезано (s00–s23) |
| `source_sheets/archive/` | отклонённые и старые листы — не использовать в игре |
| `previews/` | контрольные превью нарезки каждого листа (на шахматке видна прозрачность) |
| `tools/` | скрипт нарезки, генератор данных, образец ракурса, демо анимации |

## Как работать с ИИ-агентом

1. **Дай агенту весь пакет** (распакованную папку) как рабочую директорию или вложение.
2. **Первое сообщение агенту** — общий контекст:

   > Ты ведущий Kotlin-разработчик игр. В папке лежит пакет игры «Пустошь». Прочитай `START_HERE.md`, `TZ/00_OVERVIEW.md`, `TZ/GDD.md` и `TZ/ASSETS.md`. Ничего не пиши в код, пока не прочитаешь. Ответь коротким планом, как ты понял архитектуру, и списком вопросов, если они есть.

3. **Дальше по одному шагу:** открой `TZ/STEP_XX_*.md`, скопируй блок «Промпт для ИИ» в конце файла и отправь агенту. Не давай следующий шаг, пока не выполнены все «Критерии приёмки» текущего.
4. **После каждого шага** проверь сам: собери проект, запусти, пройди чек-лист приёмки. Если что-то не так — верни агенту список того, что не прошло.
5. **Не позволяй агенту менять `data/*.json` и `assets/` молча.** Любое изменение данных — отдельным коммитом с объяснением.

## Порядок шагов

| Шаг | Что получается в конце | Играбельно? |
| --- | --- | --- |
| 1 | Проект собирается в браузер, Android и десктоп, платформенный слой-заглушка | пустая сцена |
| 2 | Ассеты упакованы в атласы, данные загружаются и валидируются | галерея ассетов |
| 3 | Мир из чанков, биомы, тайлы, объекты, камера, коллизии, день и ночь | ходит камера |
| 4 | Герой: управление, анимация по частям, показатели выживания, смерть | герой ходит по миру |
| 5 | Инвентарь, добыча, инструменты, прочность, лут, подсветка находок | можно собирать |
| 6 | Крафт, станки, книга рецептов | можно крафтить |
| 7 | Строительство базы, тотем, аванпосты, ловушки, турели | можно строить |
| 8 | Бой, оружие, одежда, враги, звери, ИИ, ночи, кровавая ночь | можно выживать |
| 9 | Боссы, опыт и навыки, задания, ворота биомов, транспорт, обучение, сохранения | полная игра |
| 10 | Яндекс Игры и RuStore: реклама, покупки, облачные сохранения, оптимизация, релиз | релиз |

**Первая версия (MVP)** — биомы 1–3 и боссы 1–3. Данные и ассеты для биомов 4–6 уже есть: они подключаются тем же кодом, но для MVP закрыты воротами после босса 3 (флаг `mvpBiomeLimit = 3` в конфиге).

## Важные ограничения

- **Звуков в пакете нет.** На шаге 9 агент подключает бесплатные звуки с подходящей лицензией (CC0) или оставляет заглушки; лицензию каждого файла записывать в `assets/audio/LICENSES.md`.
- **API площадок и версии библиотек меняются.** Всё, что касается SDK Яндекс Игр, RuStore, рекламных сетей и версии KorGE, агент обязан сверить с актуальной официальной документацией перед реализацией (ссылки в шаге 10).
- **Масштаб спрайтов не выровнен.** ChatGPT рисует каждый объект на всю ячейку. Целевые размеры в игре заданы в `assets_manifest.json` и `data/rigs.json`; на шаге 2 агент приводит всё к ним.
